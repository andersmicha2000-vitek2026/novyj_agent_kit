# novyj_agent_kit

Склад для запуска новых **самостоятельных** агентов (свой проект, свой git —
не суб-агент внутри `agent_katya`). Для суб-агентов Кати есть свой шаблон
`agents/_template/` и команда `/new-agent` в самом `agent_katya`, этот
репозиторий их не заменяет.

Работает и с Claude Code, и с Codex — это не два набора файлов, а один:
`AGENTS.md` единственный источник правды, `CLAUDE.md` — однострочный
указатель на него (тот же приём, что уже стоит в `~/CLAUDE.md` → `~/AGENTS.md`).
Claude Code разворачивает указатель сам, Codex читает `AGENTS.md` напрямую.

## Быстрый старт

```bash
./install.sh /путь/к/новой/папке/agent_имя
```

### Альтернатива — одной репликой прямо в чат

Если удобнее не открывать терминал, а просто открыть Claude Code (или Codex)
в уже созданной папке под нового агента и сказать ему, что делать, — первое
сообщение:

> Склонируй <https://github.com/andersmicha2000-vitek2026/novyj_agent_kit> во
> временную папку и запусти в ней `./install.sh <путь до этой папки>` —
> скрипт поставит сюда AGENTS.md, CLAUDE.md, SOUL.md, MEMORY.md, GOALS.md,
> USER.md, LICENSE, замки безопасности под Claude Code и Codex, и подключит
> graphify, если он есть на машине. Папки `skills/` и `mcp/` склонированного
> репозитория сюда не копируй — это склад на будущее, берём из него по
> одному, когда реально понадобится. Временный клон после установки удали.
> Потом проведи экскурсию по дому: простым языком, с метафорами, расскажи,
> что за каждый файл и папка отвечает.

Репозиторий приватный — агенту нужен доступ под твоим GitHub-логином
(`gh auth login` или сохранённые credentials), иначе клонирование не пройдёт.

Скрипт копирует `template/` в указанную папку и делает там `git init`.
Дальше — открой Claude Code в этой папке и напиши что угодно, например
«привет». Агент сам заметит, что `USER.md` не заполнен, и начнёт знакомство:
спросит, как обращаться, чем он будет заниматься, в каком формате вести
задачи (таблица / чек-лист / заметки — выбираешь сам), какой нужен тон, и
какая сейчас главная цель. Ответы сразу лягут в `USER.md`, `MEMORY.md`,
`GOALS.md` — плейсхолдеров `{{...}}` после знакомства остаться не должно.

Если вместо ответов на вопросы попросить «покажи, что тут есть» — агент
проведёт экскурсию по структуре (`house-tour`) и только потом вернётся к
знакомству.

## Структура репозитория

```text
novyj_agent_kit/
├── install.sh          — единственная команда запуска
├── template/            — то, что копируется в новую папку агента
│   ├── AGENTS.md            — роль, правила, триггер онбординга (читают оба инструмента)
│   ├── CLAUDE.md            — одна строка "AGENTS.md", нужна только Claude Code
│   ├── SOUL.md              — характер и тон
│   ├── MEMORY.md            — долгая память, лимит 200 строк
│   ├── GOALS.md             — цели и задачи, формат задач выбирает пользователь
│   ├── USER.md              — профиль пользователя, заполняется на знакомстве
│   ├── memory/               — дневник по дням (пусто до первого использования)
│   ├── knowledge/             — справочники и разобранные случаи
│   ├── .claude/settings.json — замок для Claude Code: запрет трогать .env, rm -rf, force push/reset
│   ├── .codex/config.toml    — замок для Codex: без сети, запись только внутри папки, approval on-request
│   ├── .claude/skills/onboarding/  — интервью при первом запуске
│   ├── .claude/skills/house-tour/  — экскурсия по структуре для человека
│   └── .gitignore
├── skills/               — склад скиллов, ставятся по требованию (не всё сразу)
│   └── stop_slop/         — проверка текста на ИИ-маркеры перед показом клиенту
└── mcp/                  — шаблоны конфигов MCP-серверов, БЕЗ ключей
    ├── github.json.template
    ├── firecrawl.json.template
    └── context7.json.template
```

`install.sh` при наличии `graphify` в PATH дополнительно подключает его к
новому агенту сразу для обоих инструментов (см. «Граф вместо перечитывания
файлов» ниже) — это часть архитектуры по умолчанию, не отдельный шаг.

## Как добавить скилл новому агенту

Пока без отдельного «installer»-скилла — это лишняя машинерия, пока складе
всего один скилл. Просто скопируй папку:

```bash
cp -r novyj_agent_kit/skills/stop_slop  <папка-агента>/.claude/skills/stop_slop
```

Когда скиллов в `skills/` наберётся достаточно, чтобы ручное копирование
стало неудобным — добавить `installer`-скилл, который делает это по команде.

## Как подключить MCP-сервер

Скопировать нужный `mcp/<имя>.json.template`, подставить реальный ключ на
месте `{{...}}` (ключ — только локально, никогда не коммитить с реальным
значением) и добавить сервер:

```bash
claude mcp add-json <имя> "$(cat mcp/<имя>.json.template)"
```

## Граф вместо перечитывания файлов ([graphify](https://github.com/Graphify-Labs/graphify))

`install.sh` сам подключает `graphify` к новому агенту (Claude Code и Codex
разом), если команда `graphify` есть в PATH — не требует ничего дополнительно
делать. Пока в папке агента нечего графовать (свежий агент, почти без файлов)
это просто тихо лежит без дела — хуки graphify проверяют
`graphify-out/graph.json` и ничего не делают, если его ещё нет.

Когда у агента появится реальный код или разросшийся `knowledge/`, построить
граф один раз (и дальше обновлять после изменений):

```bash
graphify .          # построить граф
graphify update .   # обновить после правок (только AST, без API-затрат)
```

После этого агент перед чтением файлов и greп'ом сначала спрашивает граф
(`graphify query "..."`, `graphify explain "..."`, `graphify path "A" "B"`) —
это и есть конкретный механизм экономии токенов из следующего раздела, не
абстрактный совет.

Если `graphify` не установлен на машине — не критично, ставится отдельно:
`uv tool install graphifyy`, дальше `graphify install --project` (Claude Code)
и `graphify install --project --platform codex` (Codex) в папке агента.

## Экономия токенов — конкретные правила, не пожелание

- `AGENTS.md` читается целиком каждое сообщение — держать ~100 строк
  (тот же лимит, что у `СТАТУС.md` в vault Кати). Разрослось — переносить в
  `knowledge/`, не оставлять «про запас» в основном файле.
- Скиллы (`onboarding`, `house-tour`, `stop_slop`, `graphify`) читаются только
  когда вызваны — не инлайнить их содержимое в `AGENTS.md`.
- MCP-сервер добавлять только когда он реально нужен конкретному агенту —
  каждый подключённый сервер добавляет схему своих инструментов в контекст
  каждого запроса, даже если сервер не используется в моменте.
- Не верить на слово — измерять. Для плагина Claude Code: `claude plugin
  details <имя>` показывает точную оценку always-on и on-invoke токенов
  (проверено на `superpowers`: ~465 токенов всегда, остальное только по
  вызову конкретного навыка). Для своих скиллов ориентир тот же порядок
  величины — если always-on добавка тянет на тысячи токенов, это повод
  переносить содержимое в отдельный вызываемый файл, а не в `AGENTS.md`.

## Superpowers — для агентов, которые будут писать код

[obra/superpowers](https://github.com/obra/superpowers) — методология
разработки (TDD, ревью кода, план → выполнение) поверх скиллов. Не часть
`template/` (это готовый плагин, не файлы для копирования) и не для каждого
агента — только для тех, что реально будут кодить.

- Claude Code: `claude plugin install superpowers@claude-plugins-official`
  (плагин ставится на уровне пользователя — один раз на машину, а не на
  каждого агента).
- Codex: `/plugins` → найти `superpowers` → `Install Plugin` (интерактивно,
  нет CLI-эквивалента без диалога).

## unlazy — дисциплина завершения задач

[Leonxlnx/unlazy](https://github.com/Leonxlnx/unlazy) — гейты вместо честного
слова. Перед сдачей большой многоэтапной задачи агент пишет проверяемый
ledger (`CHECK:` — реальная команда, `EXPECT:` — что должно вывестись), гейт
засчитывается только если команда правда прошла и вывод совпал. Тоже не
часть `template/` — universal-установка сразу под Claude Code, Codex и
остальные инструменты, один раз на машину:

```bash
npx skills add Leonxlnx/unlazy -g
```

Вызывается явно (`/unlazy tree N <задача>`) или по триггеру вроде «не
останавливайся, пока не сделано» — не для мелких задач. Проверка безопасности
при установке: Socket — 0 предупреждений, Snyk — отметил как средний риск
(деталей инструмент не показывает, только ссылку на skills.sh), это не
блокирует установку, но стоит иметь в виду.

Есть отдельный, более жёсткий компонент — Stop-хук, который может
блокировать завершение сессии, пока гейты не закрыты
(`node <путь-к-скиллу>/scripts/install-hooks.mjs`). В базовую установку не
входит — ставить осознанно и отдельно, когда решишь, что нужна именно
блокировка, а не просто доступный скилл.

## Секреты

Ключи, токены, пароли — только в `.env` конкретного агента. Ни в `template/`,
ни в `mcp/*.template`, ни в `skills/` реальных значений быть не должно —
только имена переменных окружения.

## Защита от угона запущенного агента конкурентом

Честно: если у кого-то есть полный доступ к файлам агента и к рабочим
ключам/токенам — никакой код внутри репозитория это не остановит, это не
DRM. Реальная защита — не в коде, а в том, кто вообще получает такой доступ.
Разделение по слоям:

**Что реально не пускает (контроль доступа — организационное, не техническое):**
- Репозиторий агента — приватный, список участников минимальный, у всех
  включена 2FA на GitHub-аккаунте.
- Ключи/токены (`.env`) не передаются вместе с файлами агента даже своим —
  раздаются отдельно, по необходимости.
- Устройство, с которого работаешь с агентом, — с шифрованием диска и
  экраном блокировки; если ноутбук/сервер потерян или скомпрометирован —
  сразу ротировать все ключи из его `.env`, не только сменить пароль.

**Что уже заложено в шаблон и раздаётся с каждым агентом (снижает пользу от голой копии файлов):**
- Секреты никогда не в репозитории — у того, кто скопировал только файлы,
  нет работающих ключей, репозиторий агента сам по себе не запускается.
- `LICENSE` — прямой юридический запрет на использование в конкурентных
  целях без разрешения. Не остановит технически, но даёт основание для
  претензии, если копия всплывёт публично.
- Строка `agent-id` в начале `AGENTS.md` (генерируется `install.sh` при
  установке, у каждого агента своя) — не защита, а доказательство
  происхождения: если тексты/логика агента дословно всплывут у конкурента,
  по этой метке видно, что это именно эта установка, и с какой даты она
  существует.

**Чего в этом ките нет и что нужно решать отдельно, если агент выходит за
пределы твоего личного ноутбука** (общий сервер, наёмные сотрудники с
доступом, публичный API): аутентификация на уровне запущенного сервиса,
журнал доступа, NDA с людьми, у которых есть доступ к серверу. Это не про
файлы шаблона — скажи, если дойдёт до такой конфигурации, тогда предметно
разберём, что добавить.
